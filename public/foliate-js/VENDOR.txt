=== BROWSER CAPABILITY FLOOR — RE-DERIVE ON ANY RE-VENDOR ==========================================

The pin is not only a commit. It is also a set of browser features this code REQUIRES, and Sard
must refuse to pretend otherwise: WebView2 is the user's, not ours, and Tauri's installer only
installs it when ABSENT — it never upgrades an old one.

What the vendored code calls, and where:

  EPUB  Object.groupBy, Map.groupBy
        epub.js:178, :200, :206, :258 — the OPF metadata parser, run for EVERY book.
        Missing  =>  NO book of any kind opens.

  PDF   Uint8Array.prototype.toHex      pdf.worker.mjs:59575  (every getDocument — unconditional)
        Uint8Array.prototype.toBase64   pdf.mjs:7434          (embedded font @font-face rules)
        Uint8Array.fromBase64           pdf.mjs:24263, :24267 (signature handling)
        Missing  =>  EVERY PDF fails. This produced the reported defect:
                     "UnknownErrorException: hashOriginal.toHex is not a function".

These are enforced at runtime by FEATURE DETECTION in src/lib/runtime.ts — never by a version
number. A version check would be a second copy of the same fact and would desync the moment this
directory is re-pinned. If you re-vendor:

  1. Diff the new engines for newly-used built-ins (search for `.toHex(`, `.toBase64(`, `groupBy(`,
     `Promise.try`, `Iterator.`, `Float16Array`, `.withResolvers(`, `Array.fromAsync`, `using `).
  2. Update CAPABILITY_FEATURES / RuntimeEnv in src/lib/runtime.ts to match.
  3. Update tests/… so a missing feature still produces the runtime message rather than a raw throw.

(For reference only, never for a decision: as of the 5.5.207 pin the PDF set corresponds to
Chromium >= 140 and the EPUB set to Chromium >= 117.)
